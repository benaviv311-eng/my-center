# Raika Private Writers Room + AI — Design Spec

## Goal
להוסיף ל־**עולם ראיקה** סביבת עבודה פרטית שבה המשתמש המורשה היחיד יכול לערוך ולשמור תוכן, לשחזר גרסאות קודמות, לשנות סטטוס, ולפתוח שיחת ייעוץ AI מתוך כל כרטיס — תוך שמירה מלאה על ההפרדה בין קאנון מאושר לבין הצעות.

## עקרונות על
- האתר הציבורי של עולם ראיקה ממשיך להיות פתוח לצפייה.
- פעולות עריכה, שמירה, גרסאות וייעוץ AI זמינות רק לאחר התחברות פרטית.
- חשבון מורשה יחיד מוגדר בצד השרת; כתובת המייל עצמה **לא נשמרת בקוד הציבורי של GitHub**.
- הכניסה מתבצעת ללא סיסמה באמצעות Magic Link / OTP של Supabase Auth.
- אין לחשוף מפתח OpenAI, service-role key או סוד אחר בקוד הדפדפן או ב־GitHub.
- כל תשובת AI היא הצעה בלבד. שום תשובה, עריכה או שיחה אינה הופכת לקאנון אוטומטית.
- מעבר ל־`canon` דורש פעולה מפורשת של המשתמש המורשה.

## חוויית משתמש

### מצב ציבורי
מבקר שאינו מחובר יכול:
- לצפות בדמויות, סצנות, קווי עלילה, היסטוריה, עולם, קשרים וחדר הכותבים הציבורי.
- לחפש ולסנן תוכן.

מבקר שאינו מחובר לא יכול:
- לערוך תוכן.
- לשמור גרסאות.
- לשנות סטטוס.
- לראות שיחות AI פרטיות.
- להשתמש בייעוץ AI.

### מצב מחובר
לאחר התחברות המשתמש המורשה, כל כרטיס בחדר הכותבים ובאזורים העריכים מציג:
- `✏️ ערוך`
- `💾 שמור`
- `↩️ בטל`
- `🕘 גרסאות`
- `📝 סטטוס`
- `💬 התייעץ איתי`

## עריכה ושמירה

### שדות עריכים
בכרטיסים ניתן לערוך בהתאם לסוג הפריט:
- כותרת
- תקציר / גוף הטקסט
- מיקום מוצע בציר הסיפור
- למה זה מתאים
- מה זה עשוי לפתוח
- תגיות
- דמויות קשורות
- סטטוס

### מודל שמירה
נתוני הקאנון הבסיסיים ממשיכים להגיע מ־`raika-data.js` בגרסה הראשונה.

שינויים פרטיים נשמרים ב־Supabase כ־**override** לפי מזהה יציב של הפריט:
- `item_type`
- `item_id`
- `payload`
- `status`

בעת טעינת העמוד:
1. נטען הקאנון הציבורי מהקוד.
2. אם המשתמש מחובר, נטענים overrides פרטיים שלו.
3. override גובר על הטקסט הציבורי בתצוגה האישית בלבד.

כך נמנעת כתיבה ישירה לקוד GitHub מכל עריכה קטנה, ונשמרת האפשרות לנהל קאנון יציב בנפרד מעבודת כתיבה שוטפת.

## היסטוריית גרסאות
כל שמירה יוצרת snapshot לפני החלפת הגרסה הנוכחית.

מסך `🕘 גרסאות` מציג:
- זמן השמירה
- סטטוס באותה גרסה
- תקציר קצר של הגרסה
- `הצג`
- `שחזר גרסה זו`

שחזור יוצר גרסה חדשה; הוא אינו מוחק היסטוריה קיימת.

## שינוי סטטוס
סטטוסים נתמכים:
- `💡 הצעה` — `idea`
- `📝 בפיתוח` — `developing`
- `✅ קאנון` — `canon`
- `🗄️ בצד` — `parked`

מעבר ל־`canon` יציג אישור מפורש:
> להפוך את הגרסה הנוכחית לקאנון?

גם לאחר אישור, בגרסה הראשונה המשמעות היא "קאנון אישי מאושר" ב־Supabase. סנכרון אוטומטי בחזרה ל־`raika-data.js` ב־GitHub אינו חלק מהגרסה הראשונה, כדי למנוע שינוי קוד בלתי הפיך מכל לחיצה באתר.

## התייעצות AI בתוך האתר

### פתיחת השיחה
לחיצה על `💬 התייעץ איתי` פותחת חלונית צ׳אט בתוך הכרטיס או מגירה צדדית.

השיחה יודעת אוטומטית:
- את הפריט הנוכחי.
- את הגרסה הערוכה הנוכחית.
- את סטטוס הפריט.
- את הדמויות הקשורות.
- את קווי העלילה הרלוונטיים.
- סצנות קרובות בציר הסיפור.
- מידע קאנוני רלוונטי מתוך `RAIKA_DATA`.
- כללי העל: רעיונות אינם קאנון ללא אישור.

### שימושים אופייניים
המשתמש יכול לכתוב למשל:
- "האם זה מתאים לראי?"
- "תן לי שלוש גרסאות יותר מצחיקות."
- "זה סותר משהו בקאנון?"
- "מה מדושי היה חושב על זה?"
- "תציע המשך לסצנה הזאת."
- "איך זה מתחבר למורשת ריישין?"

### תשובת AI
כל תשובה נשמרת בשיחה ומוצגת עם פעולות:
- `העתק לטיוטה`
- `החלף את הטקסט הערוך`
- `שמור כרעיון חדש`
- `השאר כהתייעצות בלבד`

פעולות שמשנות תוכן דורשות לחיצה מפורשת של המשתמש; תשובת AI אינה משנה כרטיס באופן אוטומטי.

## ארכיטקטורת AI
הזרימה:

`GitHub Pages` → `Supabase Auth` → `Supabase Edge Function` → `OpenAI API`

Edge Function:
- מקבלת JWT תקף של Supabase.
- מאמתת שזה המשתמש המורשה.
- בונה context מצומצם ורלוונטי.
- שולחת בקשה ל־OpenAI.
- מחזירה תשובה לאתר.
- שומרת את הודעות השיחה ב־Supabase.

ה־OpenAI API key נשמר כ־secret של Supabase Edge Functions בלבד.

## מגבלת סודות וכלי פריסה
החיבור דורש `OPENAI_API_KEY` כ־secret ב־Supabase.

אם כלי האוטומציה הזמין אינו מאפשר להגדיר Edge Function secrets, תהיה **פעולה ידנית חד־פעמית** ב־Supabase Dashboard/CLI להוספת המפתח. המפתח לעולם לא יוכנס ל־GitHub, ל־JavaScript הציבורי או לטבלה נגישה מהדפדפן.

## אימות והרשאה

### כניסה
העמוד מציג כפתור `🔐 כניסה לחדר הכותבים`.

הזרימה המומלצת:
1. משתמש מזין את כתובת המייל המורשית.
2. האתר קורא ל־`signInWithOtp` עם `shouldCreateUser:false`.
3. Supabase שולח Magic Link / OTP רק אם החשבון כבר קיים.
4. לאחר כניסה, Supabase session נשמר בדפדפן לפי מנגנון הספרייה הרשמי.

כדי למנוע פתיחת משתמשים חדשים באופן חופשי, החשבון המורשה נוצר/מוזמן פעם אחת מראש ב־Supabase Auth.

### הרשאת שרת
אין להסתמך על בדיקת מייל בדפדפן בלבד.

כל Edge Function וכל טבלת כתיבה חייבות לאמת את המשתמש דרך JWT ו־RLS. הרשאת הכתיבה תוגבל ל־`auth.uid()` של המשתמש המורשה או לרשומת allowlist פרטית בצד השרת.

## סכמת נתונים

### `raika_item_edits`
שומר את הגרסה הפעילה של כל override.

שדות:
- `id uuid primary key`
- `user_id uuid not null`
- `item_type text not null`
- `item_id text not null`
- `status text not null`
- `payload jsonb not null`
- `created_at timestamptz`
- `updated_at timestamptz`
- unique: `(user_id, item_type, item_id)`

### `raika_item_versions`
שומר snapshots היסטוריים.

שדות:
- `id uuid primary key`
- `user_id uuid not null`
- `edit_id uuid not null`
- `item_type text not null`
- `item_id text not null`
- `status text not null`
- `payload jsonb not null`
- `created_at timestamptz`

### `raika_ai_threads`
שומר שיחות לפי פריט.

שדות:
- `id uuid primary key`
- `user_id uuid not null`
- `item_type text not null`
- `item_id text not null`
- `title text`
- `created_at timestamptz`
- `updated_at timestamptz`

### `raika_ai_messages`
שומר הודעות בצ׳אט.

שדות:
- `id uuid primary key`
- `thread_id uuid not null`
- `user_id uuid not null`
- `role text check in ('user','assistant')`
- `content text not null`
- `context_snapshot jsonb`
- `created_at timestamptz`

## Row Level Security
RLS מופעל על כל ארבע הטבלאות.

מדיניות בסיסית:
- `select`: רק כשה־`user_id = auth.uid()`.
- `insert`: רק כשה־`user_id = auth.uid()`.
- `update`: רק כשה־`user_id = auth.uid()`.
- `delete`: רק כשה־`user_id = auth.uid()`.

בנוסף, הרשאת Edge Function לייעוץ AI תיבדק מול המשתמש המורשה ולא רק מול עצם קיום session.

## חלוקת אחריות בקוד

### GitHub Pages
- `raika.html` — UI של התחברות, עריכה, גרסאות וצ׳אט.
- `raika-app.js` — רינדור קיים + מצב עריכה ואינטראקציות.
- `raika-private.js` — Supabase Auth, CRUD פרטי, merge של overrides, טעינת גרסאות ושיחות.
- `raika-ai.js` — UI לשיחת ייעוץ וקריאה ל־Edge Function.
- `styles.css` — עיצוב מצב מחובר, עורך, חלונית גרסאות וצ׳אט.

### Supabase
- migration לטבלאות + indexes + RLS.
- Edge Function `raika-consult`.
- משתמש מורשה יחיד ב־Auth.
- secret `OPENAI_API_KEY`.

## Context ל־AI
כדי לשמור על תשובות ממוקדות ועלויות סבירות, לא שולחים כל פעם את כל עולם ראיקה.

ה־context נבנה בשכבות:
1. כללי קאנון קצרים וקבועים.
2. הכרטיס הנוכחי במלואו.
3. הדמויות הקשורות.
4. קווי העלילה הקשורים.
5. 2–4 סצנות סמוכות/רלוונטיות.
6. עד N הודעות אחרונות בשיחה.

אם המשתמש שואל במפורש על נושא רחב יותר, אפשר להרחיב את ה־context לפי תגיות.

## פרטיות ושמירה
- שיחות AI פרטיות אינן נחשפות באתר הציבורי.
- overrides וגרסאות פרטיות אינם נשלחים לגולשים לא מחוברים.
- `context_snapshot` נשמר כדי להבין בעתיד על סמך איזה מצב קאנוני ניתנה תשובת AI.
- אין לשמור API keys, service-role tokens או magic links בטבלאות תוכן.

## מצבי שגיאה
- לא מחובר → פעולות פרטיות חסומות עם בקשת התחברות.
- session פג → בקשת התחברות מחדש.
- Edge Function ללא secret → הודעה ברורה שהייעוץ עדיין לא מחובר; העריכה והשמירה ממשיכות לעבוד.
- OpenAI זמנית לא זמין → השיחה נשארת שמורה והמשתמש יכול לנסות שוב.
- שמירה נכשלת → הטקסט נשאר בעורך ואינו נמחק.

## גרסה ראשונה
הגרסה הראשונה תכלול:
- Magic Link/OTP למשתמש מורשה יחיד.
- מצב ציבורי מול מצב מחובר.
- עריכה ושמירה של כרטיסים.
- גרסאות ושחזור.
- שינוי סטטוס עם אישור מיוחד לקאנון.
- שיחות AI שמורות לפי כרטיס.
- context אוטומטי של עולם ראיקה.
- פעולות "העתק לטיוטה" ו"שמור כרעיון חדש".

לא נכלל בגרסה הראשונה:
- עריכה שיתופית לכמה משתמשים.
- סנכרון אוטומטי של קאנון בחזרה ל־GitHub.
- העלאת תמונות קאנוניות.
- חיוב משתמשים או הרשאות צוות מורכבות.

## קריטריוני הצלחה
- משתמש לא מחובר אינו יכול לכתוב או להשתמש ב־AI.
- רק המשתמש המורשה יכול לבצע פעולות פרטיות.
- עריכות נשמרות בין מכשירים לאחר התחברות.
- כל שמירה יוצרת גרסה שניתנת לשחזור.
- AI מקבל context רלוונטי ולא משנה תוכן לבד.
- כל רעיון AI נשאר מחוץ לקאנון עד אישור מפורש.
- אין שום secret בקוד GitHub הציבורי.
- האתר הציבורי ממשיך לעבוד גם אם Edge Function או OpenAI אינם זמינים.
